# kintone-image-compressor

English version: [README.md](./README.md)

kintoneの添付ファイルフィールドに画像を付ける前に、ブラウザ内で縮小・再エンコードする。4〜12MBのスマホ写真を長辺1920pxに縮小して品質0.8のJPEGに再エンコードすると、多くの場合数百KBに収まる。処理はすべてブラウザ内とkintone REST APIで完結し、外部サーバーには何も送らない。

再エンコードでGPS位置情報を含むEXIFメタデータが落ちるため、保存前に写真から位置情報を取り除く用途にも使える。

## スクリーンショット

スクリーンショットは `docs/` に置いてここからリンクする。

1. 既定値の設定画面。
2. 編集画面のボタン（ドラッグオーバー状態を含む）。
3. 5ファイル処理後の結果一覧（成功・スキップ・非対応・失敗の各行と合計行）。
4. レコード詳細画面での処理前後のサイズ比較。

## 機能

- レコードの作成・編集画面（デスクトップ・モバイル）のスペースフィールドにボタンを1つ追加する。
- ファイル選択ダイアログを開くか、ボタンへのドロップを受け付ける（ドロップはデスクトップのみ）。
- 画像形式は拡張子ではなく、ファイルの先頭バイトで判定する。
- 長辺を設定値まで縮小し、JPEG・PNG・WebPを再エンコードする。JPEGと（設定により）不透明PNGはJPEGに、透過PNGはPNGのまま、WebPはJPEGになる。
- GIF・SVG・HEIC・アニメーションPNG・1億画素超の画像・サイズしきい値未満のファイルは、変更せずそのまま添付する。
- 処理結果を1件ずつアップロードし、選択した順に対象の添付ファイルフィールドへ追加する。既存の添付ファイルは残る。
- レコードの保存は利用者が行う。プラグインが行うのはフィールドを埋めるところまで。

## インストール

1. プラグインのzipをビルドする。
   ```
   npm install
   npm run pack
   ```
   `npm run pack` が `dist/plugin.zip` を出力する。初回実行時には `private.ppk` も生成される（git管理外）。以降のビルドでも同じ `private.ppk` を使い回せば、プラグインIDが変わらない。
2. kintoneのシステム管理を開き、「プラグイン」から `dist/plugin.zip` をアップロードする。
3. アプリにプラグインを追加し、下記の設定を済ませてアプリを更新する。

## 設定

| 設定 | 内容 | 既定値 |
| --- | --- | --- |
| ボタン設置スペース | ボタンを表示するスペースフィールド | なし（必須） |
| 添付先フィールド | 新しいファイルを追加するフィールド | なし（必須） |
| 長辺の上限（px） | 長辺をこのサイズまで縮小する | 1920 |
| JPEG品質 | 0.5〜0.95。低いほど小さく粗くなる | 0.8 |
| スキップしきい値（KB） | これより小さいファイルは無加工で添付する | 300 |
| 不透明PNGをJPEGに変換 | 透過のないPNGをJPEGでエンコードする | オン |
| 撮影日を先頭に付ける | 再エンコードしたファイル名に `YYYYMMDD_` を付ける | オフ |
| ボタンのラベル | ボタンに表示する文字列 | 画像を圧縮して添付 |

## ファイルの扱い

- 形式は先頭バイトで決める。中身がPNGの `.jpg` ファイルはPNGとして扱い、出力の拡張子は実際の出力形式に合わせる。
- 圧縮するのはJPEG・PNG・WebP。GIF・SVG・HEIC・アニメーションPNG・1億画素超の画像・スキップしきい値未満のファイルはそのまま添付する。
- 再エンコードしたファイルが元より小さくならない場合は元ファイルを添付し、そのEXIFは残る。
- 再エンコードはGPS位置情報を含むEXIFをすべて取り除く。撮影日をファイル名に残したい場合は「撮影日を先頭に付ける」をオンにする。
- ファイル名が重複したら、大文字小文字を区別しない比較で ` (2)`、` (3)` を付ける。
- 0バイトのファイルと100MB超のファイルは添付せず、失敗として表示する。

## 制限事項

- 標準の添付ファイルフィールド自身のファイル選択には割り込まない。そこで選んだファイルは圧縮されないので、このプラグインのボタンを使うこと。
- HEICはデコードも変換もしない。ブラウザにHEICデコーダーがないため、HEICファイルはそのまま添付される。
- アニメーションGIFとアニメーションPNGはそのまま添付する。アニメーションの縮小はしない。
- 出力はJPEGかPNGのみ。Safariの `toBlob('image/webp')` 対応が不安定なため、WebP・AVIFでの出力は使わない。
- iOS Safariでは、端末の上限を超えるサイズのキャンバスでエンコードに失敗することがある。その場合は無加工での添付にフォールバックする。

## プライバシー

外部送信はない。プラグインが使うのはブラウザと、ログイン中ユーザーのセッションでのkintone REST APIのみ。APIトークンは保持せず、localStorageにも書き込まない。

## 開発

```
npm install
npm run typecheck   # tsc --noEmit
npm test            # Vitest unit tests for the core logic
npm run build       # builds desktop.js, mobile.js, config.js into dist/
npm run pack        # builds, then packs dist/plugin.zip (generates private.ppk once)
```

`test/e2e` に主要フローのPlaywright仕様がある。開発用のkintone環境に対して実行し、接続情報は `KINTONE_BASE_URL`、`KINTONE_USERNAME`、`KINTONE_PASSWORD`、`KINTONE_APP_ID` から読む。CIには含めていない。
